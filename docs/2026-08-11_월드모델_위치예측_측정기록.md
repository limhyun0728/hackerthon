# 2026-08-11 월드모델 위치 예측 — 진단과 처방

C-JEPA 월드모델의 유닛 위치 예측이 **"안 움직인다" 가정보다 나빴다**는 것을 발견하고,
원인을 특정해 고친 기록이다. 최종적으로 RED 위치 예측 오차가 t+3s 기준 12.5m → 8.1m로
내려갔고, 미관측 RED가 불확실 원 안에 있을 확률이 50.5% → 95.8%가 되었다.

측정 도구는 `worldmodel/measure_belief_coverage.py`이고, 별도 언급이 없으면
`--scenarios 60 --candidates 16`, seed 11, 14개 맵 전체다. 시나리오는 학습 에피소드와
무관하게 새로 생성된다(병력 2~10명, 배치·임무 무작위).

---

## 1. 발단 — 손실은 내려가는데 지표는 나빠졌다

`cjepa_statickv.pt`(400 에피소드/1200 epoch 학습)에서 이어 학습하자 예측 오차가
악화됐다. 그런데 학습 손실은 정상적으로 내려갔다.

```
statickv5 (버퍼만, 100 에피소드 추가 학습)
  loss          0.5538 → 0.4264   (시작점 0.4811보다 낮아짐)
  latent        0.3137 → 0.2360
  future_state  0.0878 → 0.0699
      ↑ 그 사이 RED 위치 오차 t+3s 16.8 → 25.7m (악화)
```

**손실과 실측 지표가 반대로 움직인다.** 이것이 이 문서 전체의 출발점이다.

---

## 2. 근본 원인 — 위치가 손실의 1%도 아니다

월드는 x축 40유닛(400m)이라 **정규좌표 1.0 = 200m**다. 위치 오차를 `future_state`
손실(유닛 feature 8개의 평균 MSE) 기준으로 환산하면:

| 위치 오차 | 정규좌표 | `future_state`(0.07) 대비 기여 |
| --------- | -------- | ----------------------------- |
| 3.9m      | 0.0195   | **0.1%**                      |
| 9.6m      | 0.0480   | **0.8%**                      |
| 12.9m     | 0.0645   | 1.5%                          |
| 25.7m     | 0.1285   | 5.9%                          |

**위치를 9.6m에서 25.7m로 2.7배 망가뜨려도 손실은 0.0036 늘 뿐이다.** hp·ammo·alive는
0~1 범위를 꽉 채워 쓰므로 그쪽을 조금만 개선하면 위치 손해가 덮인다. 최적화는 정직하게
손실을 내렸고, 그 과정에서 위치를 버렸다.

지형이 유닛 gradient를 4.8~57배 희석하던 문제(`compute_training_losses`의
`future_dynamic` 주석)와 같은 종류다.

## 2.1 정지 가정보다 나쁘다

DEVS 실측(`output/statickv_rule` 60 에피소드 `soldier_log.csv`, RED 표본 19,014건):

```
              실제 이동거리(=정지가정 오차)    월드모델 예측오차
RED  t+1s          3.9m (중앙 0.0m)               9.6m    ← 2.5배 나쁨
RED  t+2s          7.7m                          12.4m
RED  t+3s         11.2m                          12.5m
RED  t+6s         21.0m                          17.9m    ← 여기서만 모델이 이김
```

RED는 양쪽 모두 `UrbanRedPolicy`가 몰므로 등가 비교다. **1200 epoch 학습한 모델이 1초 뒤
위치를 "안 움직인다"보다 못 맞혔다.** 데이터 양의 문제로 설명되지 않는다.

## 2.2 구조적 원인

`rollout_cjepa_future`가 `state_decoder`로 **절대 좌표를 통째로 디코딩**한다. "안 움직였다"를
표현하려면 디코더가 입력 좌표를 토큰 병목으로 재현해야 하고, 그 복원 오차만 2.02m가
바닥으로 깔린다(§15). 지형에는 이미 같은 이유로 마지막 관측값을 쓰는 예외가 있는데
유닛에는 없었다.

---

## 3. 배제된 가설 — 다시 시도하지 말 것

전부 측정으로 배제했다.

| 가설                                | 반증                                                  |
| ----------------------------------- | ----------------------------------------------------- |
| optimizer state 미복원              | 복원해도 25 에피소드 만에 14.4m                       |
| batch 크기(128 vs 원본 32)          | 32로 줄여도 더 빨리 악화                              |
| statickv 이후 코드 변경(`71ed07b`)  | 추가된 인자를 아무도 안 넘겨 dormant                  |
| **월드모델 window replay buffer**   | v4(버퍼+seed) ep0025 13.9m vs 버퍼 없는 v3 14.4m      |
| **학습 부족 / 표본 이동**           | 100 에피소드(500 epoch)에도 세 런 모두 시작점 미회복  |

버퍼 실험은 세 팔로 확인했다. 어느 것도 시작점(12.5m)에 못 갔고, seed를 넣은 쪽(v4)이
오히려 더 나빴다 — 실행 궤적만 담긴 seed가 반사실 window 비중을 희석한 것으로 보인다.

**학습 부족 가설**은 표본 이동이 실재하고(destroy_and_reach 23%→33%) v3가 한 번
되돌아온 것도 사실이라 한동안 살아 있었으나, ep0100까지 봤을 때 세 런이 서로 다른
방향으로 흩어져 학습 궤적이 아니라 배회로 판정했다.

## 4. 처방 ① 위치 잔차 예측 (`CJEPA_POSITION_RESIDUAL=1`)

영-초기화한 `unit_position_delta` head가 predictor 토큰에서 (Δx, Δy)를 뽑아
**마지막 관측 위치에 더한다.** 디코더와 나란히 같은 토큰을 받는 구조이고,
학습(`predict_cjepa_sequence` 미래 프레임)과 추론(`rollout_cjepa_future`) 양쪽에
동일하게 걸린다.

영-초기화라 켠 직후 예측이 정확히 "안 움직임"이 되어, 정지 기준선에서 출발한다.

**주의**: 이 플래그로 학습한 checkpoint는 반드시 플래그를 켜고 써야 한다. 끄면 delta
head가 무시돼 위치가 전부 어긋난다.

## 5. 처방 ② 위치 전용 손실 (`--unit-position-loss-weight`)

`_unit_position_loss`가 **살아 있는 unit의 x/y만** 따로 MSE를 낸다. 전사자·지형·임무는
제외한다. `combat_state`(가중치 4.0), `damage_delta`(8.0)와 같은 패턴이다.

가중치 30이면 손실 기여가 32.7%로 `latent`(29.6%)를 넘는다.

## 5.1 L1 (`CJEPA_POSITION_LOSS_L1=1`)

L2는 이중 분포에서 평균으로 수렴한다. RED 1초 변위는 **중앙값 0m / 평균 3.9m**라
"대부분 정지, 가끔 10m 점프"인 분포다. L1은 중앙값으로 수렴하므로 "기본은 정지"가 된다.
부수적으로 gradient가 오차 크기에 무관해 작은 오차에서도 힘이 안 빠진다(L2는 축당 4m에서
기여가 1.8%로 소멸).

값 스케일이 약 10배 커지므로 가중치는 30 → 3으로 재조정한다.

## 6. 결과 (200 에피소드)

```
                              t+1    t+2    t+3    t+4    t+5    t+6    포함률   건물   상한초과
정지 가정 기준선               3.9    7.7   11.2      —      —   21.0       —      —        —
statickv (출발점)              9.6   12.4   12.5   17.3   17.5   17.9   50.5% 10.85%    6.49%
statickv 잔차만(Δ=0)           0.0    9.8    9.8   18.9   18.9   18.9  100.0%  0.00%    0.00%
statickv5 ep0100 (절대좌표)   11.3   16.0   17.6   21.9   21.9   22.6   30.6% 15.59%    5.67%
posonly  ep0200 (잔차 없음)   12.2   17.6   18.9   21.4   22.0   22.0   32.2% 15.60%    5.56%
residual ep0200 (잔차만)       7.5    8.3    8.3   16.5   16.7   16.7   83.0%  1.18%    1.69%
respos   ep0200 (잔차+위치)    5.7    8.0    8.3   14.8   14.6   14.7   95.9%  3.88%    0.45%
```

**세 가지가 확정됐다.**

1. **잔차가 필수다.** `posonly`(잔차 없이 위치손실만)는 200 에피소드를 돌고도 t+3s
   18.9m로 최악이다. 시작점보다도 나쁘다. 잔차 없이는 위치 손실을 아무리 키워도
   절대 좌표 디코딩의 한계를 못 넘는다.
2. **위치 손실이 잔차 위에서 작동한다.** t+1s 5.7 vs 7.5m, 포함률 95.9 vs 83.0%.
3. **ep0025에서의 조기 판정은 틀렸다.** 그 시점엔 respos(11.6m)가 residual(9.8m)보다
   나빠 보였으나 200 에피소드에서 뒤집혔다. 위치 손실은 오래 돌려야 효과가 나온다.

## 6.1 일반화 — 홀드아웃에서 무너지지 않는다

`--maps-root`를 심볼릭 링크로 나눠 학습맵 10개와 홀드아웃 4개를 따로 쟀다.

|                  | 학습맵 10개 | **홀드아웃 4개** | 차이   |
| ---------------- | ----------- | ---------------- | ------ |
| RED t+1s         | 5.7m        | **5.6m**         | −0.1   |
| RED t+3s         | 8.1m        | **8.7m**         | +0.6   |
| RED t+6s         | 15.1m       | **14.1m**        | −1.0   |
| 미관측 포함률 t+1s | 95.8%       | **95.4%**        | −0.4%p |
| 건물 통과        | 3.34%       | **4.52%**        | +1.2%p |

홀드아웃은 `euljiro`(120동, 학습 맵과 같은 조밀도), `jamsil`, `assembly`(4동),
`yongsan`(2동)이다. **밀도 이상치까지 포함해도 t+3s 7% 차이**에 그친다. 건물 통과가
1.2%p 오른 것이 유일하게 눈에 띄는 저하다.

## 6.2 물리 클램프 A/B (`CJEPA_ROLLOUT_PHYSICS`)

`_enforce_unit_physics`는 BLUE에서 크게 듣고 RED에서는 거의 안 든다. 상한이 1.5유닛인데
RED 실제 상한은 1.0(`red_policy.py` max_step)이라 RED는 클램프를 거의 안 거친다.

|                | 클램프 OFF | 클램프 ON |
| -------------- | ---------- | --------- |
| 최대 스텝      | 28.9 m/s   | 15.0 m/s  |
| BLUE t+1s 오차 | 18.6m      | **12.7m** |
| RED t+1s 오차  | 10.0m      | 9.6m      |
| RED 이탈률     | 44.9%      | 44.9%     |

**팀별 상한으로 나누면 RED도 개선될 가능성이 있다.** 미적용 상태다.

## 7. 오차 분해 — 방향이 아니라 타이밍이다

홀드아웃 `euljiro` 3 에피소드에서 오차 벡터를 실제 진행방향 성분(세로)과 수직
성분(가로)으로 분해했다.

```
        오차   실제이동  예측이동   세로   가로   정지오예측  (정지 건수)
t+1s    6.5     0.5      6.3      6.5    4.9      6.4      135/144
t+3s   10.0     7.2     10.6      8.2    6.2      7.7       47/144
t+6s   18.6    16.5     16.1     17.6    8.4     13.4       40/136
```

**세로 오차가 가로의 2배가 넘는다.** 방향은 대체로 맞고 얼마나 갔는지가 틀린다.

더 결정적인 것은 **정지 오예측**이다. t+1s에 실제로 움직인 유닛은 144건 중 9건뿐인데
(94%가 정지) 모델은 평균 6.3m를 움직인다고 예측한다. t+1s 오차의 거의 전부가 여기서
나온다. L1 처방(§5.1)의 직접 근거다.

## 7.1 t+3s → t+4s 계단

모든 모델에서 같은 자리에 계단이 있다.

```
                              t+1    t+2    t+3    t+4    t+5    t+6   t3→t4
statickv (원본)                9.6   12.4   12.5   17.3   17.5   17.9   +4.8
statickv 잔차만(Δ=0)           0.0    9.8    9.8   18.9   18.9   18.9   +9.1
respos ep0200                  5.7    8.0    8.3   14.8   14.6   14.7   +6.5
```

**예측을 아예 안 하는 정지 기준선에서 계단이 제일 크다.** 모델 특성이 아니라 데이터
특성이다. RED의 실제 누적 이동 중앙값이 `0 → 10 → 10 → 20 → 20 → 28.9m`로 10m 격자를
밟는데(평균은 3.9/7.7/11.2/14.6/17.8/21.0으로 매끄럽다), 그 격자의 위상이 t+4에서
어긋난다.

## 8. 검증한 계약

구현 과정에서 단위 검증으로 확인한 것들이다.

- `_unit_position_loss`: 전사자 제외, 지형·임무 제외, x/y만, `feature_mask` 반영,
  분모 = 축2 × 생존유닛 × 프레임 — 7개 케이스 전부 기대값 일치
- 속성별 블록 인코더: 같은 좌표면 UNIT/TERRAIN/MISSION의 위치 블록이 **완전히 동일**,
  hp만 바꾸면 state 블록만 움직임, x만 바꾸면 position 블록만 움직임
- **버그 하나를 검증이 잡았다**: 블록 인코더의 `output_norm`을 전체 차원 LayerNorm으로
  두면 평균·분산이 블록을 넘나들어 블록 분리가 무효화된다. 블록별 LayerNorm으로 고쳤다.

## 9. 진행 중 / 미해결

- **respos2 / residual2 / resposl1** — 400 에피소드 연장 (seed 8484, 같은 에피소드)
- **block** — 속성별 블록 + 차원 축소(embedding 128→64, hidden 2048→256, 파라미터
  11.33M→0.85M) + 잔차 + L1, 처음부터 600 에피소드. 스모크 미실시
- **팀별 이동 상한** — `_enforce_unit_physics`가 전 유닛 1.5유닛인데 RED는 1.0이어야 함
- **지형 크기** — `width_norm`/`height_norm`이 identity 블록에 있다. 기하 정보라 위치
  블록이 맞지만 위치 블록을 타입 공용 2차원으로 잡아 자리가 없었다. 충돌 예측에 영향
  가능
- **relative position bias** — attention logit에 쌍 기하 bias를 더하는 안. 블록으로
  충분한지 보고 판단
- **CEM 제안 분포가 factorized** — 유닛별 독립 샘플링이라 협조 기동을 표현 못 함.
  평가는 결합인데 제안은 주변분포뿐이다. 위치 예측과는 별개 축
